# 打包与安装验收

安装包工作仍在进行中。以下命令生成未签名的本地测试产物，不会发布版本，也不代表全部平台均已验收。

在对应目标平台使用 Node 24.12.x、pnpm 11.0.9 和原生编译工具。先执行 `pnpm install --frozen-lockfile`、`pnpm lint`、`pnpm typecheck`、`pnpm test`。

| 原生构建环境 | 命令 | 产物 |
| --- | --- | --- |
| Apple Silicon Mac | `pnpm package:mac:arm64` | arm64 DMG |
| Intel Mac | `pnpm package:mac:x64` | x64 DMG |
| Windows x64 | `pnpm package:win:x64` | x64 NSIS 安装包 |

产物位于 `dist/installers/`。执行 `node scripts/checksums.mjs` 生成 SHA256SUMS.txt。GitHub 工作流仅可手动触发，在不同原生系统构建并上传临时工作流产物，不创建公开 Release。除非执行报告记录了真实运行，否则不能视为已验证。

当前安装包没有经过验证的开发者签名或公证，系统可能提示开发者身份未知或信誉不足。仅测试来源及校验值可信的产物，不要关闭系统级保护。公开发布是另一个里程碑。

macOS 打开 DMG，将 Unvar 拖入 Applications；Windows 运行当前用户安装程序并选择安装目录。替换已有应用前请完全退出 Unvar。卸载应用不会主动删除工作区，工作区备份和系统凭据需分别管理。

升级前完全退出应用，将整个工作区复制到备份位置。新版本启动后若目录已移动，请重新选择原工作区。迁移前自动备份 SQLite，迁移失败不能删除并重建研究数据。工作区备份不包含系统凭据密钥。不要用旧版本直接打开已迁移的数据；需要回退时使用另一份升级前备份。

每个目标系统均需在干净环境验证：安装启动、原生数据库及凭据访问、笔记标签持久化、完整 Signal → Writing 流程、人工确认门槛、Pi/Jev 四种开关组合、错误与取消、导出、退出重启及旧工作区升级。记录真实引擎和模型、系统架构、产物校验值和签名状态。构建成功不能替代安装验收，合成测试也不能替代真实研究和四周自用。

另见[模型配置](network-setup.md)及[工作区备份](workspace-folders.md)。

隔离排查或安装验收可使用可执行文件参数 `--unvar-profile=/绝对路径/空配置目录`。请选择新建空文件夹，应用会使用独立配置和工作区，不更改默认配置。
