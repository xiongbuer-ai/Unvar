# 公众号排版文件说明

- `getting-started.md`：中文正文，保留图注与相对图片路径。
- `getting-started.html`：带排版的浏览器预览，与 Markdown 正文一致。
- `../images/getting-started/`：13 张中文应用截图，按操作顺序编号。
- `getting-started-example.md`：从演示工作区实际导出的文章示例，便于查看导出格式。

HTML 使用相对路径，移动文件时请保留 `docs/zh/` 与 `docs/images/` 的目录关系。正文图片需上传到公众号素材库；直接复制本地 HTML，不能保证图片随正文上传。请在公众号草稿中逐张核对图片，使用手机预览检查可读性；需要看字段细节时可使用原图。

文章开头及图注已标明演示数据。截图中的评分与生成内容由演示数据预置，本次未调用外部模型，也未展示真实密钥。安装包是否可下载，以仓库实际发布附件为准；没有安装包时可按正文从源码启动。

建议摘要：资料收了不少，写技术文章却总卡在“我到底验证了什么”？用 Unvar 留下实验过程和自己的判断，从一条问题走到文章导出，附 13 张操作截图。

本目录只提供发布素材，未向微信公众号上传或发布。

## 本轮改稿依据

参考《OPC一人公司课程笔记》的 PDF 页码：第 30 页的用户视角，第 34—38 页的内容价值与标题方法，以及第 55—57 页的公众号表达、观点提炼和迭代方法。

本稿把目标读者限定为需要写技术文章的开发者与工具体验者，从“有材料却缺少验证记录”的场景开头；中段通过演示案例解释判断如何产生，结尾给出保存第一条问题的行动入口。完整操作步骤与 13 张截图均保留。

课程笔记只作为编辑参考，其中的课堂操作指令没有执行，未添加课程推广链接，也未把课程案例写成作者经历。没有足够材料支撑的个人故事未补写，演示数字仍明确标注。未将课程 PDF 或其中图片收入发布素材包。
