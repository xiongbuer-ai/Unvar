# 本地工作区与同步

[English](../en/workspace-folders.md) | 简体中文

在“设置 → 工作区文件夹”中选择：

- **在文件管理器中打开**：查看当前工作区。
- **复制工作区到…**：选择一个独立的空文件夹，复制当前数据并切换。原工作区保留，不删除。目标不能是当前工作区、其子目录或父目录。
- **打开已有工作区…**：选择同步或备份得到的完整 Unvar 工作区，切换后重启。不会合并两个工作区。

切换前保存尚未提交的表单。应用在重启前停止后台分析、等待任务退出、完成数据库备份，再记住新路径。复制失败不会覆盖源数据，不完整的目标不能作为新工作区使用。首次升级自动将旧的 `userData/unvar.db` 及资料、导出、备份复制到 `userData/workspace`，旧文件保留。

## 文件结构

```text
工作区/
  unvar-workspace.json     # 格式与版本标识
  unvar.db                # 全部研究内容、模型配置、研究方向与任务记录
  config/interface.json   # 界面语言偏好
  materials/              # 本地资料
  exports/                # Markdown 导出的默认位置
  backups/                # 数据库迁移备份
  cache/                  # 可重建缓存，不进 Git
  logs/                   # 运行日志，不进 Git
  .gitignore
  README.md
```

数据库覆盖收件箱记录、标签、网页正文、主张、问题、评分、实验及日志、研究结论、文章、模型配置和流程状态。模型 API Key 不写入数据库或工作区，仍使用当前设备系统钥匙串；在新设备上重新配置。已有钥匙串内容不迁移、不删除。

设备在 Electron `userData/workspace-location.json` 记录所选文件夹的绝对路径，这个定位文件不参与同步。Electron 浏览器缓存、窗口运行数据留在本机。工作区可以在另一台机器的不同路径打开。找不到已选文件夹时，启动会提示重新定位，不会悄悄创建空库。

## Git 与云盘的使用顺序

1. 完全退出 Unvar（macOS 使用 Cmd+Q；只关窗口不代表退出）。正常退出会将 WAL 内容写回数据库。
2. 等待云盘上传完成，或在工作区执行 Git 提交与推送。
3. 在另一台设备完成下载/拉取后，打开该工作区。
4. 同一时间只在一台设备编辑。

SQLite 是二进制数据库，不能用普通文本 merge 合并两台设备的修改。这一版本支持整个工作区的顺序同步与版本管理，不提供实时协作或冲突合并。遇到冲突先保留两份完整副本，再选择需要打开的版本。不要让云盘用远端数据库覆盖正在运行的本地数据库。

`.gitignore` 排除 `unvar.db-wal`、`unvar.db-shm`、缓存、日志和临时文件；**不要在运行时只复制或提交 `unvar.db`**，未提交到主文件的内容可能仍在 WAL 中。应用内“复制工作区”使用 SQLite backup，包含已提交到 WAL 的写入。云盘通常不会读取 `.gitignore`，所以云盘同样必须在应用完全退出后同步；必要时运行期间暂停同步。

Git 不保留空文件夹；应用启动会重建资料、导出、备份、配置、缓存与日志目录。源工作区内自建的其他顶层文件或 Git 历史不在应用复制范围中，需要时自行复制；应用复制包含上述业务数据目录，自动生成工作区说明及忽略规则。

## 备份与恢复

使用「复制工作区到…」创建完整副本；该操作也会切换当前工作区，如需继续使用原目录，可再次「打开已有工作区…」。也可以在完全退出应用后，备份整个工作区文件夹。

恢复时选择「打开已有工作区…」，打开完整的备份文件夹。恢复不会合并现有数据，请保留当前工作区以便回退。备份不包含 API Key。
